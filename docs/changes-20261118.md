# 2026-11-18 安装与配置向导恢复原版界面

`v0.0.1-naive` 起改用 Go 版配置向导后，提问文字和顺序与原版 V2bX 差别较大，且 HTTP/DNS 证书会强制要求填写 ACME 邮箱，
不填直接报错 `ACME email is required` 退出。本次恢复原版的界面，内部的校验、原子写入和失败回滚保持不变。

## 配置向导（`V2bX generate`）

- 提问恢复原版：`请输入机场网址`、`请输入面板对接API Key`、`是否设置固定的机场网址和API Key？`、`请选择节点核心类型`、
  `请输入节点Node ID`、`请选择节点传输协议`、`请选择是否为reality节点？`、`请选择是否进行TLS配置？`、`请选择证书申请模式`、
  `请输入节点证书域名`、`是否继续添加节点配置？(回车继续，输入n或no退出)`。
- 不再询问 ACME 邮箱，与原版一样默认使用 `v2bx@github.com`。
- 证书模式恢复原版三项（http / dns / self）；self 模式下证书目录已有证书则直接使用，否则自动生成自签证书。
- 不固定面板地址时，后续每个节点会重新询问机场网址和 API Key（原版行为）。
- 协议菜单按核心显示可用项：xray 只列 Shadowsocks/Vless/Vmess/Trojan；singbox 额外列 Hysteria/Hysteria2/AnyTLS/Naive/TUIC。
  输错时重新询问，不再直接退出。
- API Key 恢复为可见输入（原版行为）；DNS API 参数和 SOCKS 密码仍不回显。
- 保留本仓库新增项，回车即为原版默认：监听 IP（singbox 有 IPv6 时默认 `::`，否则 `0.0.0.0`；hysteria2 不询问）、
  singbox 住宅 SOCKS 出口、Naive HTTP/3。
- 从管理菜单或 `V2bX generate` 生成配置后，与原版一样自动重启 V2bX；取消或未生成时不重启。

## 安装脚本

- 恢复原版提示：`开始安装`、`检测到 V2bX 最新版本：x，开始安装`、`V2bX x 安装完成`、安装后显示管理命令列表、
  首次安装询问 `检测到你为第一次安装V2bX,是否自动直接生成配置文件？(y/n)`。
- SHA256 校验、失败回滚、备份保留等机制不变。

## 证书

- 向导检测原版证书位置 `/etc/V2bX/fullchain.cer`、`/etc/V2bX/cert.key`：若是该域名且未过期的证书，直接使用该路径，
  不再重新申请。原版升级上来的节点不会因为证书路径变化而重新走 ACME。
- http 模式申请证书时若 TCP 80 已被其他程序占用，错误信息里会说明原因和处理办法（停止占用程序、改用 dns 模式或放入已有证书）。

## 证书申请失败不再反复请求 Let's Encrypt

VPS 测试时 TCP 80 被其他程序占用，http 模式申请证书失败后 V2bX 退出，systemd 每 10 秒重启一次，每次都重新向
Let's Encrypt 下单，很快触发 `429 too many failed authorizations (5) ... in the last 1h`，80 端口空出后还得再等限流解除。

- http 模式申请前先检查 TCP 80 能否监听；不能则直接报错并给出处理办法，不向 Let's Encrypt 发任何请求。
- 申请失败后在证书目录写入 `acme-cooldown.json`，冷却期内（依次 5、10、20、40 分钟，之后每次 1 小时；
  若 Let's Encrypt 返回了 `retry after` 时间则至少等到该时间）重启也不会再次申请，错误信息里会显示冷却截止时间和上次错误。
- 申请成功后自动删除该文件；问题处理好后想立即重试，手动删除该文件再重启 V2bX 即可。
